# HOMEY — تحديث المحافظات وحذف طلبات التجربة (3 نوفمبر 2026)

**داخل هذا الملف:** مجلد `src` المعدّل بالكامل + مجلد `sql` وفيه ملف واحد باسم `HOMEY_GOVERNORATES_AND_TEST_ORDER_DELETE_2026-11-03.sql`.

## خطوات التثبيت (مهمة بالترتيب)

1. **اعمل نسخة احتياطية من قاعدة البيانات** داخل Supabase قبل التنفيذ، واحفظ نسخة من مجلد `src` الحالي. الحذف دائم عند استخدام الزر.
2. من **Supabase → SQL Editor → New Query** افتح ملف الـ `.sql` المرفق، وانسخ محتواه **كاملًا** وشغله بـ **Run**. التحديث لا يحذف أي طلب موجود تلقائيًا.
3. اختبر النتيجة الأخيرة من SQL: `active_governorates_out_of_27` لازم تكون **27**. الملف يعرض جدول أسعار الشحن للمراجعة.
4. **سعر شحن `0` مقبول:** المحافظة تظل مفعّلة والعميل يقدر يكمّل الطلب. ملف SQL المعدّل لا يحتاج سعرًا موجبًا ولا يغيّر أسعار الشحن المسجلة حاليًا (بما فيها `0`).
5. انسخ **مجلد `src` الموجود داخل الـZIP** فوق مجلد `src` في **جذر المشروع** عندك (وليس فوق الجذر نفسه). احتفظ بباقي ملفات مشروعك (`package.json`، إعدادات Supabase/Vercel، إلخ) كما هي. بعدها اعمل Build/Deploy بالطريقة المعتادة على Vercel.
6. افتح **لوحة التحكم → الإعدادات والربط → أسعار الشحن حسب المحافظة** وراجع الأسعار. أي محافظة عندها سعر `0` تفضل متاحة بشحن مجاني، والمحافظات الموجودة أصلًا لا تتغيّر أسعارها. المحافظات الجديدة تمامًا تُضاف بسعر `0` حتى تعدّله أنت، والنطاق العام الجديد لمحافظة موجودة يأخذ أقل سعر مسجل لنفس المحافظة (حتى لو صفر).
7. من نافذة خاصة اختبر **طلبًا تجريبيًا** بمحافظة كانت مش متاحة قبل كده (زي الوادي الجديد أو شمال سيناء)، وجرّب اسم منطقة غير موجود في قائمة المناطق القديمة. بعد التأكد افتح **لوحة التحكم → الطلبات** وحدّد الطلب التجريبي واحذفه بالتأكيد بكلمة **«حذف»**.

## النتيجة المطلوبة

- الـ27 محافظة المصرية متاحة للطلب دائمًا من ناحية إعدادات الشحن، **حتى لو رسوم الشحن 0 جنيه**؛ لكل محافظة نطاق عام لا يشترط كتابة اسم منطقة حرفيًا.
- زر إيقاف المحافظة اتشال من الإعدادات المصرية، وSQL يرفض تعطيلها أو إزالة آخر نطاق عام لها.
- إدارة الطلبات تعرض **Checkbox** أمام الطلبات التي يمكن حذفها، واختيار كل الطلبات المؤهلة في الصفحة، وزر **حذف الطلبات المحددة**، وزر حذف طلب تجريبي من تفاصيله.
- حذف تجارب الشراء **نهائي وبصلاحية الأدمن فقط**، بعد كتابة كلمة «حذف»، ويشمل إزالة البيانات التابعة للطلب وتحرير حجز المخزون الفعّال داخل معاملة واحدة. الطلبات الملغاة التي فُك حجزها بالفعل لا يُعاد فك حجزها مرة ثانية.
- الحذف مقيد بالطلبات **غير المدفوعة وغير المشحونة** (حالات الطلب: جديد/تم التأكيد/قيد التجهيز/ملغي، وحالات الدفع: غير مدفوع/بانتظار الدفع/فشل الدفع). طلب به إيصال تحويل أو إثبات دفع لا يقبل الحذف حتى لو كانت حالة الدفع لم تُحدّث. في كل مرة يمكن حذف حتى **50 طلب**.
- السجل `homly_test_order_deletion_log` يحتفظ فقط برقم الطلب، ومُعرفه، وتاريخ الحذف، ومُعرف الأدمن، بدون بيانات شخصية، لمراجعة عمليات الحذف الإدارية.

## تنبيهات

- **لم يتم تشغيل SQL على حساب Supabase الفعلي أو نشر التعديل على Vercel** من هنا. النجاح الفعلي يتطلب تنفيذ SQL، رفع `src`، ثم تجربة أوردر حقيقي في وضع اختبار.
- إذا انقطع الإنترنت أو Supabase أو ظهر نقص بالمخزون، لن يمكن إجبار النظام على حفظ الطلب. الإصلاح يزيل **حظر المحافظات** فقط ولا يلغي التحقق من المخزون والمدفوعات.
- الحذف لا ينشئ استرداد أموال ولا يحذف أي ملف إيصال من Supabase Storage؛ وللأمان هو يرفض حذف الطلبات صاحبة إيصالات أو مدفوعات، ويوقف العملية إذا كانت هناك علاقات بقاعدة البيانات لم يمكن تنظيفها بأمان.
- ملف SQL قابل لإعادة التشغيل دون إنشاء محافظات مكررة أو حذف طلبات تلقائيًا. ولكن لو حصلت رسالة خطأ نفّذ الإصلاح أولًا قبل النشر.
- الملفات تخص **`src` فقط** كما طلبت، وليست مشروع التشغيل كاملًا.

## ملاحظة مهمة عن النسخة السابقة

لو شغّلت النسخة السابقة بعد وضع قيمة احتياطية مثل `7000`، ممكن تكون بعض أسعار المحافظات الصفر اتغيّرت إلى 70 جنيه بالفعل. النسخة المعدّلة **لا ترجّع الأسعار تلقائيًا إلى صفر** لأنها لا تقدر تميّز بين الأسعار المقصودة والتغييرات السابقة. راجع أسعار المحافظات من لوحة التحكم وعدّل كل محافظة أنت عايز شحنها مجاني إلى `0`.
