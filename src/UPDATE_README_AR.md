# تحديث السورس — العملاء والطلبات وExcel

## التركيب
1. خذ نسخة من src الحالي ثم استبدله بمجلد src الموجود داخل ZIP. احتفظ بـ public وملف البيئة وملفات إعداد المشروع عندك.
2. من الطرفية داخل مشروعك نفّذ:

```bash
npm install fflate@0.8.2 saxes@6.0.0
```

3. شغّل ملف SQL المنفصل `HOMY-SOURCE-UPDATES.sql` في Supabase SQL Editor مرة واحدة. هذا تحديث لقاعدة مشروعك الحالية homly_*، وليس لقاعدة المشروع الآخر products/product_variants.
4. أعد تشغيل المشروع. راجع أن رقم واتساب مفعّل ومحفوظ بزر **حفظ ونشر للعملاء** من الإدارة > محتوى وتصميم المتجر > واتساب.

## العميل والطلب
- يختار العميل المنتجات ويملأ بياناته ثم يؤكد. SQL يحفظ العميل في homly_customers ويربطه بالطلب في homly_orders، مع حفظ البنود والمبالغ على الخادم في نفس المعاملة.
- نفس رقم الهاتف يستخدم سجل عميل واحدًا ويحدّث آخر عنوان له، لكن بيانات كل طلب قديم تظل محفوظة كما كانت. رقم الهاتف هنا وسيلة تجميع سجلات وليس إثبات هوية أو تسجيل دخول.
- صفحة العملاء في الإدارة تعرض آخر البيانات المحفوظة. الزوار لا يقدروا يقرؤوا سجلات العملاء أو يبحثوا عنها برقم الهاتف.
- اختيار «تذكّر بياناتي على هذا الجهاز» يحتفظ ببيانات العميل ومنطقة الشحن محليًا لتعبئتها في الطلب القادم. إلغاؤه يمسح النسخة المحلية. هذا لا يلغي حفظ بيانات الطلب في قاعدة المتجر.
- بعد تأكيد الحفظ تظهر النتيجة ورقم الطلب، ثم تفتح رسالة واتساب برقم الإدارة المنشور وبكل تفاصيل العميل والطلب. العميل يضغط إرسال داخل واتساب. إذا منع المتصفح الفتح التلقائي، يظل زر الرسالة ظاهرًا.
- الطلب يظهر في الإدارة بحالة جديد/بانتظار المراجعة؛ تأكيد المتجر والتسليم والدفع حالات مستقلة. قائمة الطلبات تتحدث تلقائيًا خلال 8 ثوانٍ وعند توافر Realtime.
- إعادة المحاولة بنفس البيانات تستخدم مفتاح الطلب نفسه لمنع التكرار. لا تُسجل أسعار أو أرقام طلبات وهمية في المتصفح.
- هذه النسخة تستدعي homly_checkout عبر RPC المحمية بقواعد التحقق والتسعير وحدود الطلبات لكل هاتف. لا تحتاج نشر Edge Function جديدة لتشغيل التحديثين؛ يجب تنفيذ SQL المنفصل.

## Excel
- من المنتجات بجوار إضافة منتج: «تحميل قالب Excel فارغ» و«استيراد Excel».
- القالب XLSX حقيقي وفارغ من بيانات المنتجات والصور. فيه ورقتا البيانات والصور، وورقة تعليمات لكل الحقول. القالب مضمّن داخل السورس؛ لا تحتاج نقل ملف public إضافي.
- simple منتج منفرد، base أصل منتج متفرع لا يباع وحده، وvariant وحدة بيع من تفريعاته. parent_key يربط التفريعة بـ item_key للأصل. اقرأ تعليمات القالب قبل أول رفع.
- كل وحدة بيع لها SKU ورابط وسعر بالجنيه ومخزون مستقل. التصنيفات موجودة مسبقًا؛ category_refs يقبل slug أو UUID، ولأكثر من قسم استخدم |.
- اختياران أو ثلاثة عبر أزواج الاسم والقيمة؛ حتى 6 خصائص اختيار من خلال extra_options_json. المواصفات عبر specifications_json. كل اختيارات الأصل لها نفس أسماء الخصائص وتركيبات مختلفة.
- الصور في ورقة منفصلة. source_type=file مع مسار نسبي ثم إرفاق مجلد/ZIP/صور منفصلة، أو url لرابط HTTPS مباشر يسمح بـ CORS. صور الأصل مشتركة مع تفريعاته التي ليس لها صور خاصة. المنتج المنشور يحتاج صورة مشتركة أو صورة لكل وحدة بيع.
- اضغط فحص الملف. الأخطاء تمنع الحفظ وتظهر بالسطر والحقل، ويمكن تحميل تقريرها. بعد نجاح الفحص اضغط بدء الاستيراد.
- يمكن رفع أكثر من 1000 منتج في ملف واحد؛ لا يوجد حد مصطنع لعدد المنتجات. هناك حد 100 تفريعة لكل عائلة لأن وظيفة حفظ المنتجات الحالية تفرضه. كل عائلة وصورها في نفس الملف.
- الحدود العملية: Excel حتى 64MB، الصورة حتى 5MB، ZIP حتى 128MB مضغوط و256MB بعد الفك وحتى 20 ألف صورة. Excel نفسه يحد الورقة إلى 1,048,576 صفًا. قسّم الدفعات الضخمة حسب ذاكرة جهازك.
- حجم تفاصيل العائلة الواحدة يخضع لحد وظيفة الحفظ الحالية (قرابة 200 ألف حرف JSON)، وهو غير حد عدد المنتجات في الملف. كل عائلة تُحفظ بمعاملة مستقلة. الناجح يظل محفوظًا عند فشل عائلة أخرى. يمكن الإيقاف بعد العائلة الحالية والمتابعة أو إعادة الفاشل فقط. بعد تحديث الصفحة أعد اختيار نفس الملف والصور.
- إعادة نفس البيانات تتجاوز المحفوظ ولا تعيد المخزون أو المنتجات المحذوفة. نفس كود الاستيراد ببيانات مختلفة يُرفض؛ تعديل الموجود يكون من محرر المنتجات.
- قد تبقى ملفات صور غير مستخدمة بعد فشل حفظ عائلة أو انقطاع الاتصال؛ لا تُحذف تلقائيًا لتجنب حذف صور عملية نجحت وفُقد تأكيدها. المسارات ثابتة حسب الصورة لمنع التكرار عند إعادة المحاولة.

## التحقق
فحوص TypeScript وبناء الإنتاج واختبارات التحقق من القالب والمنتجات والرسائل وحفظ العميل وخصوصيته واستيراد المنتجات نجحت محليًا. لا تتضمن هذه الحزمة بيانات اتصال سرية، ولم نعدّل قاعدة Supabase الحية من هنا.
