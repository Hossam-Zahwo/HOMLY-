# تحديث تأكيد الطلب وواتساب

ابدأ بملف **CHECKOUT_SETUP_AR.md** لتفعيل تسجيل الطلب وفتحه على واتساب رقم الإدارة. ملف SQL المطلوب: `database/CHECKOUT_UPDATE.sql`، ووظيفة الخادم مرفقة داخل `supabase/functions/homly-checkout`.

# هومي — الواجهة الكاملة مع حفظ Supabase

الحزمة مبنية على مشروعك الفعلي `src.zip`. رجعت الصور والواجهة والأقسام والمنتجات الأولية، مع الإضافة والتعديل والحذف من قاعدة البيانات بدل حفظ تجريبي في المتصفح.

## التجهيز مرة واحدة
1. في Supabase > SQL Editor شغّل محتوى `database/RESTORE_STARTER.sql` بالكامل. هذا تحديث لقاعدة مشروعك الموجودة `homly_*`، وليس سكربت إنشاء قاعدة جديدة.
2. احتفظ بإعدادات مشروعك الصحيحة في `.env.local` حسب `.env.example`. لا تضع service_role أو أي مفتاح سري في الواجهة.
3. نفّذ `npm ci` ثم `npm run dev`.
4. سجّل الدخول كمدير من `/admin/login`. عند أول دخول ناجح تتجهز بيانات البداية تلقائيًا في قاعدة البيانات: 6 منتجات و8 وحدات بيع/تفريعات و6 أقسام، ومحتوى الصفحة الرئيسية إن كانت فارغة. افتح المتجر بعدها. لا تتم التهيئة من حساب زائر.

## كيف تعمل البيانات
- الصور الأصلية مرفقة في `public/images`، ومراجعها وأسماء المنتجات وأسعارها وأقسامها تُحفظ في Supabase.
- التهيئة معاملة واحدة: لو فشل حفظ جزء منها فلا تُحفظ بيانات بداية ناقصة. تظهر رسالة الخطأ ويمكن إعادة المحاولة.
- يسجّل النظام اكتمال التهيئة في جدول مستقل. تكرار الدخول أو تحديث الصفحة لا يعيد المنتجات المحذوفة، حتى لو حذفت كل المنتجات والأقسام لاحقًا.
- لا يُستبدل محتوى منشور له أقسام بالفعل. لا تُكرر الأقسام ذات نفس الرابط أو المنتجات ذات نفس أول SKU. حالة الخطأ تمنع عرض نجاح وهمي.
- بعد التهيئة، أضف منتجًا أو قسمًا أو صورة جديدة من لوحة الإدارة واضغط حفظ؛ تُرسل البيانات إلى Supabase تلقائيًا ولا تحتاج كتابة SQL لكل إضافة.
- التعديلات على الهيرو والنصوص والأقسام والترتيب تتم من «محتوى وتصميم المتجر». احفظ المسودة ثم انشر لتظهر للعملاء. يمكن حذف أقسام الصفحة من نفس المحرر.
- زر «حذف» في قائمة المنتجات يزيل المنتج من العرض وقائمة الإدارة. لحماية الطلبات القديمة يُحتفظ بسجله داخليًا كمنتج محذوف مؤرشف، وتُوقف تفريعاته عن البيع.
- زر «حذف القسم» متاح بقائمة الأقسام. إذا كان مرتبطًا بمنتجات غير محذوفة، انقلها أولًا لقسم آخر أو احذفها؛ سيظهر تنبيه واضح.
- لا توجد طلبات أو تقييمات أو أرقام طلبات تجريبية. الطلب الحقيقي يجب أن يؤكده الخادم.

## مهم
لا تُشغّل ملفات `tests/fixtures` في قاعدة مشروعك؛ هي قواعد اختبار محلية فقط. الملف المطلوب لهذا التحديث هو `database/RESTORE_STARTER.sql`.

لم يُنفذ التحديث على قاعدة حسابك من هنا. احتفظ بوظائف Supabase الأصلية وصلاحيات المدير وEdge Functions التي يستخدمها مشروعك. عند غياب وظيفة أو جدول ستظهر رسالة الخطأ بدل الحفظ في المتصفح.

## التحقق المحلي
نجحت فحوص TypeScript، اختبارات القراءة والحفظ، وبناء الإنتاج. اختبارات PostgreSQL المحلية تحققت من تشغيل التحديث مرتين، وصلاحيات المدير، وتهيئة البيانات دون تكرار، واستمرار حذف المنتج بعد إعادة التهيئة، ومنع حذف قسم مرتبط بمنتجات.

```bash
npm run typecheck
npm test
npm run test:sql
npm run build
```
